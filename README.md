# 循环租用资产履约

追踪数码设备从寄租、入仓、验机、出库、交付、归还、维修到再次流转的全过程。
每件实物使用**不可复用的资产身份**；所有权（寄租人）、使用权（承租人）与
平台保管责任分别记录为半开时间区间 `[start, end)`，出库/归还事件切换保管与
使用区间，二者在任一时点互斥。

## 核心设计：事件溯源 + 确定性折叠

所有业务事实都是不可变事件（登记、入仓、验机、租期确认、出库/交付/归还扫描、
差异计算、双方确认、争议、维修、召回、仓间转运、报废）。资产状态、责任区间、
结算与统计**只由事件流折叠得到**：

- 命令按 `idem_key` 幂等去重；同一事件重复提交只受理一次。
- 物流回调按业务键归一（运单节点只前进、重复扫码不产生重复区间）。
- 账本保存去重后的事件全集，每次投递后按 `(occurred_at, event_id)`
  **全量重放**。因此同一批事件无论打乱顺序、分块到达还是重复投递，
  归位结果、拒绝集合与账本指纹（`GET /digest`）必然相同——两次计算收敛到同一账本。
- 生命周期与电子废弃物减量统计（`GET /stats`）只从真实流转推导，
  平台不接受任何客户端上报的汇总值（未知上报命令直接判为 `invalid`）。

## 关键规则

- **版本化验机**：标准（检查项与分级上限）与计费规则按 `id+version` 注册即冻结，
  同版本内容不可篡改；每次验机引用具体版本，逐项保存等级与证据哈希，
  并生成证据包哈希（标准版本 + 全部结果）供复核。等级越界、检查项不在标准中、
  缺少证据哈希的验机一律拒绝。
- **先算后认**：归还复检后由系统按出库/归还两次验机与当时版本的费率规则先计算
  差异提案（含逐项扣款），经承租人与寄租人双方确认后才成为最终结算；
  任一方拒绝即进入争议，已拒绝提案不能被另一方确认翻盘。
- **争议即证据保全**：争议单开启后资产进入 `evidentiary_hold` 冻结区间，
  解除前不可出租、出库、转运或送修；维修与召回状态同样阻断出库与转运。
- **免押资格快照**：免押资格只在租期确认瞬间写入快照，之后政策变化不回溯，
  只影响尚未确认的租期。
- **调度资格**：随机时点查询（`GET /assets/{id}?at=…`）返回该时点的保管责任仓、
  适用验机标准版本与是否可调度；争议中的设备在任何时点都不出现在调度清单。
- **仓间转运**：可跨仓发起以满足次日达，但不得穿越维修/召回/证据保全状态；
  `pickup → in_transit → arrival` 扫码乱序、重复回调归一为同一结果，
  到达后保管责任区间切换到目的仓。

## 命令（POST /commands，单条或数组）

`register_asset` · `consign` · `inspect` · `confirm_rental` · `scan_outbound` ·
`confirm_delivery` · `scan_return` · `compute_discrepancy` · `confirm_settlement` ·
`raise_claim` · `resolve_claim` · `start_repair` · `finish_repair` ·
`issue_recall` · `clear_recall` · `start_transfer` · `transfer_scan` · `retire_asset`

每条命令携带 `asset_id`、`at`（毫秒或 ISO 时间）与 `idem_key`。
响应给出逐条受理结果（`accepted` / `duplicate` / `invalid`）与当前账本指纹；
被业务规则拒绝的事件可在重放拒绝列表中复现（相同输入永远相同拒绝）。

## HTTP 接口

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/health` | 服务身份与健康状态 |
| POST | `/commands` | 投递一条或一批命令（幂等） |
| GET | `/assets/{id}` | 资产当前完整事实视图 |
| GET | `/assets/{id}?at=<ms|ISO>` | 任一时点：保管责任/验机版本/流转资格 |
| GET | `/dispatch[?at=…]` | 当前（或时点）各仓可调度出库清单 |
| GET | `/standards` | 已注册的验机标准与计费规则版本 |
| GET | `/stats` | 由流转推导的生命周期与减量统计 |
| GET | `/digest` | 账本指纹（用于收敛性核对） |

## 运行与验收

```bash
python3 service.py --check          # 基础检查 + 主管验收场景（收敛/争议阻断）
python3 service.py --port 8000      # 启动服务
npm test                            # 契约 + 16 项领域规则 + 4 项 HTTP API 测试
```

`--check` 场景把两台相机的完整流转（含乱序/重复物流回调、争议冻结期的
违规出租/转运/送修）分别以顺序、洗牌、分块三种方式各投一遍，断言三个账本
指纹一致、60 个随机时点视图一致、争议设备在争议后任何时点都不可调度。
